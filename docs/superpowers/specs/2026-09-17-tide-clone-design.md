# Tide 潮汐自製版 — 設計規格

**日期**：2026-09-17
**狀態**：待審閱
**目標**：複製一套 tide-tw.app 的核心功能供個人使用，並針對自用情境做適當優化。

---

## 1. 目標與非目標

### 目標

每個交易日收盤後，自動彙整三大法人在 76 個主題板塊的資金進出，用四象限泡泡圖呈現「哪些板塊在漲潮、哪些在退潮」，並提供排行榜與板塊成分股檢視。

### 非目標（明確不做）

| 不做的項目 | 理由 |
|---|---|
| 盤中即時資料 | 三大法人買賣超為收盤後彙整，盤中不存在此資料。原站亦僅提供盤後（官方定價頁載明約 18:30 前更新） |
| 上櫃以外的興櫃市場 | 資料格式再一套，覆蓋率提升有限 |
| PWA / Service Worker / 手機殼 | 自用，瀏覽器直接開啟即可 |
| 帳號登入 / Supabase | 無多使用者需求 |
| 推播通知 | 需 VAPID 金鑰與常駐服務 |
| 金流 / 訂閱 | 無 |
| 情緒投票 / 排行榜戰績 | 社群功能，單人無意義 |
| A/B feature flag / GA 追蹤 | 營運用途，自用純成本 |

## 2. 原版架構還原（分析結論）

| 層 | 原站實作 |
|---|---|
| 前端 | Vanilla JS，單一 HTML 內聯全部 JS/CSS（972 KB），無 React/Vue/D3/Chart.js |
| 繪圖 | 手刻 SVG（泡泡圖）＋ canvas 2d（走勢圖） |
| 行情資料 | 靜態 JSON 檔（`/data/*.json`），離線批次每日產出後上 CDN |
| 後端 | Supabase（Auth + Postgres + 24 個 RPC），**僅服務使用者功能，與行情資料完全解耦** |
| 金流 | 藍新金流定期定額 ＋ Apple IAP |
| CDN | Cloudflare（`/data/` 有 Bot 防護） |

**關鍵結論**：行情資料層與使用者層解耦，因此自用版可只複製前者，做成零後端的純靜態站。

## 3. 資料來源（全部實測通過，2026-09-17）

| # | 用途 | 端點 | 單位 | 歷史回溯 |
|---|---|---|---|---|
| 1 | 上市法人買賣超 | `twse.com.tw/rwd/zh/fund/T86?response=json&date=YYYYMMDD&selectType=ALL` | **股數** | ✅ 支援 |
| 2 | 上市收盤行情 | `twse.com.tw/rwd/zh/afterTrading/MI_INDEX?response=json&date=YYYYMMDD&type=ALL` | 元 | ✅ 支援 |
| 3 | 對帳基準 | `twse.com.tw/rwd/zh/fund/BFI82U?response=json&dayDate=YYYYMMDD&type=day` | **金額** | ✅ 支援 |
| 4 | 上櫃法人買賣超 | `tpex.org.tw/www/zh-tw/insti/dailyTrade?type=Daily&sect=EW&date=YYYY/MM/DD&response=json` | **股數** | ✅ 支援（實測至少回溯至 2024/09） |
| 5 | 上櫃收盤行情 | `tpex.org.tw/www/zh-tw/afterTrading/otc?date=YYYY/MM/DD&type=EW&response=json` | 元 | ✅ 支援 |

備援：`openapi.twse.com.tw/v1/opendata/t187ap03_L` 提供 1,094 家上市公司的官方 33 類產業別，作為主題板塊以外的分類備案。

### 已知端點陷阱（實測記錄）

1. **T86 給的是股數不是金額**，必須 join 收盤價換算：`金額 = 買賣超股數 × 收盤價`。
2. **`STOCK_DAY_ALL` 不可用於歷史回補** — 回傳 CSV 而非 JSON（`response=json` 被忽略），且忽略 `date` 參數永遠回最新日。原站使用此端點，故僅能逐日累積。本專案改用 `MI_INDEX`。
3. **`tpex.org.tw/openapi/v1/*` 不支援日期參數** — 實測帶 `date=1150916` 仍回傳最新日。必須使用上表第 4、5 支端點。
4. **TPEX 欄位名含髒空白**，例如 `" Foreign Investors..."`、`"Dealers -TotalSell"`。Parser 需正規化欄位名。
5. **TPEX 日期為民國年格式**（`115/09/16`），需轉換。
6. **MI_INDEX 的「漲跌(+/-)」欄位含 HTML**，例如 `<p style= color:red>+</p>`，需剝除標籤。
7. **T86 單日回傳 16,893 筆，其中僅 1,075 筆為 4 位數代號**（普通股/ETF），其餘 15,704 筆為權證、114 筆為 5 位數代號。必須過濾。
8. 非交易日（假日）回傳空表，非錯誤，需正常處理。

## 4. 資料管線

Python 腳本，本機執行，手動觸發。

```
[抓取]   四支端點（T86、MI_INDEX、TPEX insti、TPEX otc）
           ↓  原始回應存入 data/raw/{market}/{YYYYMMDD}.json
[快取]   已存在的日期直接讀檔，不重打交易所
           ↓
[清洗]   過濾非 4 位數代號（剔除權證）
         剝除 HTML 標籤、正規化 TPEX 欄位名、民國年轉西元
         比對 sectors.yaml，輸出無法對應的死代號報表
           ↓
[換算]   淨買超金額（億元） = 買賣超股數 × 收盤價 / 1e8
           ↓
[彙總]   依 sectors.yaml 將個股金額加總至 76 個板塊
         個股可同時屬於多個板塊（沿用原站設計）
           ↓
[計算]   net_5d_yi / net_20d_yi / accel / 象限 / 泡泡半徑
           ↓
[輸出]   data/daily/{YYYYMMDD}.json   每日板塊快照
         data/latest.json              前端讀取的主資料集
         reports/unmapped_{YYYYMMDD}.txt  死代號報表
```

**錯誤處理**：任一端點失敗則該日整體失敗並保留既有輸出，不產出部分資料（避免靜默的錯誤數字）。請求之間加入間隔，避免對交易所造成負擔。

## 5. 指標定義

沿用原站定義（自其公開前端程式碼還原）：

```
net_5d_yi   = 近 5 個交易日板塊淨買超合計（億元）
net_20d_yi  = 近 20 個交易日板塊淨買超合計（億元）
accel       = net_5d_yi / 5 − net_20d_yi / 20

X 軸        = net_5d_yi
Y 軸        = accel
泡泡半徑    = clamp(22 + |net_20d_yi| / max20 × 33, 22, 55)
              其中 max20 = 所有板塊 |net_20d_yi| 的最大值

象限分類：
  net5 >  0 且 accel >  0  →  漲潮（錢在流進而且越流越快）
  net5 >  0 且 accel <= 0  →  輪動（還在流進但慢下來了）
  net5 <= 0 且 accel >  0  →  觀察（流出但在減緩）
  否則                      →  退潮
```

## 6. 板塊定義與維護

76 個主題板塊、713 檔去重成分股，來源為原站公開前端程式碼中內聯的對照表。

**外部化為 `sectors.yaml`**，格式：

```yaml
AI 伺服器組裝:
  - "2317"
  - "2382"
矽晶圓:
  - "6182"
  - "3532"
```

### 覆蓋率現況（實測，2026-09-16 資料）

母體定義為「上市名單 ∪ 上櫃名單」（1,094 ＋ 1,014 ＝ 2,108 檔）。
覆蓋率（板塊）＝ |該板塊成分股 ∩ 母體| / |該板塊成分股|。

```
713 檔成分股
  ├─ 可取得法人資料   598  (84%)
  ├─ 興櫃              39  (6%)   興櫃無三大法人買賣超日報，任何來源皆不可得
  └─ 已下市／併購      76  (11%)

板塊覆蓋率 >= 90%：48 / 76
          80-90%：19 / 76
           < 80%： 9 / 76
```

覆蓋率 < 80% 的 9 個板塊及其成因：

| 板塊 | 覆蓋率 | 主要成因 |
|---|---|---|
| 太陽能產業 | 55% | 昱晶 3514、綠能 3519、昇陽光電 3561、旺能 3599 於 2018 年整併為 6443 聯合再生 |
| 第三代半導體 | 60% | 璨圓 3061、元砷 3214、廣鎵 8199 等已下市；另有 2 檔興櫃 |
| 面板產業 | 60% | 勝華 2384、華映 2475、奇美電 3009、東貝 2499 等下市或改組 |
| 光感測與元件 | 60% | 晶電 2448 與隆達 3698 整併為 3714 富采投控 |
| EMS 電子代工 | 65% | 神達 2315 改號為 3706；致伸 2336 已換號 |
| 電池關鍵材料 | 64% | 3 檔興櫃、2 檔已下市 |
| 光學鏡頭 | 67% | 2 檔興櫃、4 檔已下市 |
| 石英頻率控制 | 75% | 奇力新 2456 併入國巨 |
| 被動元件 MLCC | 76% | 奇力新 2456 併入國巨；旺詮 2437 等已下市 |

**共同特徵**：這 9 個板塊皆為經歷過產業大整併的成熟板塊，原站的對照表保留了整併前的舊代號。
反證：HBM、CXL、玻璃基板、智慧型手機、陸運與宅配等新興板塊覆蓋率為 100%，無歷史包袱。

因此死代號的清理是有規則可循的，非雜亂髒資料：
- **已下市／併購（76 檔）**：查繼受公司代號後替換（例：3514 → 3576、2448 → 3714、2315 → 3706）
- **興櫃（39 檔）**：直接移除，資料源頭不存在

管線需輸出此報表供人工清理，不得靜默忽略。

### 清理結果（2026-09-18 已執行）

清查記錄見 `reports/dead-codes-2026-09-18.md`，清理後的定義見 `sectors.yaml`。

| 指標 | 清理前 | 清理後 |
|---|---|---|
| 成分股（去重） | 713 | 601（上市 366／上櫃 235） |
| 可取得法人資料 | 598（84%） | 601（100%） |
| 板塊覆蓋率 >= 90% | 48 / 76 | 76 / 76 |
| 板塊覆蓋率 < 80% | 9 | 0 |

處置方式：繼受替換 16 檔（其中 2 檔由名稱比對程式判定，14 檔依產業整併判斷，繼受代號皆已驗證仍在市場）、
移除 99 檔（已下市無繼受 43、興櫃 39、無交易所記錄 17）。

清理後板塊成分股數：最小 3、中位數 11、最大 21。

## 7. 前端

單一靜態網頁，vanilla JS，無框架、無圖表庫，沿用原站的手刻 SVG 作法。

**頁面組成**
- 泡泡圖：四象限，X/Y 軸如上，點擊泡泡展開該板塊成分股
- 排行榜：板塊依 `net_5d_yi` 排序，可切換當日／近 5 日
- 板塊詳情：成分股列表，含個股淨買超與漲跌
- 深色／淺色主題切換（沿用原站 `theme_mode` localStorage 作法）

**資料流**：頁面載入 → `fetch('data/latest.json')` → 渲染。無其他網路請求。

## 9. 驗證標準

| # | 驗證項 | 通過條件 |
|---|---|---|
| 1 | 總額對帳 | 見下方「對帳公式」，誤差率 < 0.5% |
| 2 | 個股抽驗 | 隨機抽 3 檔，逐檔換算金額與交易所官網人工比對一致 |
| 3 | 板塊對應率 | 死代號報表中的代號數 = 0（清理完成後） |
| 4 | 指標正確性 | 對已知板塊手算 net5 / net20 / accel，與管線輸出一致 |
| 5 | 象限分類 | 四個象限各至少有一個板塊落入，且分類符合定義 |
| 6 | 前端渲染 | `latest.json` 載入後泡泡圖正確繪製，點擊展開成分股 |

### 對帳公式

```
誤差率 = |Σ(T86 全體證券 三大法人買賣超股數 × 收盤價) − BFI82U 合計買賣差額|
         ÷ (BFI82U 合計買進金額 + BFI82U 合計賣出金額)
通過條件：誤差率 < 0.5%
```

**必須使用 T86 的全體證券**（含權證），不可使用管線過濾後的 4 位數代號集合。
BFI82U 統計範圍涵蓋整個集中市場，權證是自營商避險部位的大宗；實測若僅計 4 位數
代號，2026-09-16 的誤差達 76.96%，無法對帳。

**分母須為成交總額，不可為淨額。** 淨額在買賣接近平衡的交易日會趨近零，
導致相對誤差爆增。實測比較（5 個交易日）：

| 日期 | 淨額為分母 | 成交總額為分母 |
|---|---|---|
| 2026-09-16 | 0.77% | 0.023% |
| 2026-09-15 | 1.32% | 0.172% |
| 2026-09-11 | 0.31% | 0.049% |
| 2026-06-10 | 4.04% | 0.366% |
| 2026-04-20 | 9.54% | 0.029% |

以收盤價回推整日成交本身即有誤差，此項為量級健檢（可捕捉欄位錯位、單位錯誤），
非精確比對。結構正確性另由驗證項 7 的算術恆等式保證。

### 驗證項 7：欄位對應恆等式（零容差）

各來源的欄位分組可由算術恆等式確認，實測於 17,779 列資料上零違反：

```
T86：        [4]外陸資 + [7]外資自營商 + [10]投信 + [11]自營商 == [18]三大法人
             [14]自營自行 + [17]自營避險 == [11]自營商
TPEX insti： [10]外資合計 + [13]投信 + [22]自營合計 == [23]三大法人
             [4]外陸資 + [7]外資自營商 == [10]外資合計
             [16]自營自行 + [19]自營避險 == [22]自營合計
```

此為 parser 欄位對應是否正確的決定性測試，任何違反即表示欄位錯位。

開發採 TDD：先對每支 parser 寫針對真實回應樣本的測試，再寫實作。

## 10. 相對原站的優化

| # | 優化 | 解決什麼問題 |
|---|---|---|
| 1 | 拆分檔案（HTML/JS/CSS 分離） | 原站 972 KB 單檔全內聯，為首屏速度犧牲可維護性；自用版不需要付此代價 |
| 2 | 板塊表外部化為 `sectors.yaml` | 原站硬編於 JS 中，無法調整 |

| 5 | `data/raw/` 增量快取 | 回補 20 個交易日約需 80 次請求；有快取則重跑不重打交易所 |
| 6 | 改用 `MI_INDEX` 取代 `STOCK_DAY_ALL` | 原站端點無法回補歷史，只能逐日累積；改用後可一次回補完整 20 日 |

## 11. 已知風險與限制

1. **部分板塊清理後成分股偏少**。覆蓋率問題已由死代號清理解決（84% → 100%），但代價是板塊縮水：
   太陽能產業 20→11、面板產業 20→12、光感測與元件 20→13、第三代半導體 15→9。
   成分股少的板塊，單一權值股的進出會主導整個板塊數字。介面應顯示各板塊成分股數，供判讀時參考。
   另有 2 個板塊原始定義即少於 5 檔（功率電感 3、前段製程設備 4），非清理所致。
2. **板塊表會過期**。概念股組成隨產業變化，`sectors.yaml` 需人工定期檢視。
3. **端點無正式契約**。這些是交易所網站的內部 API，格式可能變更且無版本承諾。Parser 需在格式不符時明確失敗而非產出錯誤數字。
4. **板塊對照表為原站的整理成果**。個人使用無虞；若日後公開發布，應自行重新編製板塊定義。
5. **無盤中資料**。若日後需要，盤中僅能取得量能與漲跌等代理指標，無法取得法人買賣超；且 TWSE MIS 端點無 CORS 標頭，屆時必須新增後端。
